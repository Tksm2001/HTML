## ゲーム設計「かためだるま / One-Eyed Daruma」

- 片目しか入っていない巨大だるま。**入っている目の側の半分しか見えない**。見えない側なら動いても平気
- だるまはときどき目をチカチカさせて、入れ替える（安全な側が逆転。集団が一斉に反対側へ走る＝撮りたくなる瞬間）
- 見られている側で動くと、吹っ飛ばされるのではなく**小さなだるまに変えられる**。揺れるだけ。仲間が 3 秒長押しで救出
- だるまの足元の黄色い台で長押しすると**もう片方の目を入れて勝ち**。だるまが「完成」する
- 友達と遊ぶ理由（救出、だるま役モード）を最初から組み込む。新アルゴリズムの「友達と遊んだ日数」対策

- 勝利時にだるまが背を向けていると完成した顔が見えない → 勝ったら正面を向く
- 捕まっている間に HUD が「にげろ」に戻る → 捕まっている間は「仲間を待て」を出し続ける

- 未確認: 救出（2 人必要。Studio の「Test > Clients and Servers」で 2 人にして確認する）

**2026-10-06（2 回目）: 利用者の初プレイの感想を受けて追加・変更。**
感想: 「ハードバージョンが欲しい」「片方だけ（片目の視界）がよく分からない」「だるまがだるまに見えない」「ステージにこだわりたい」
- 片目の視界は売りなので残し、見て分かるようにした: 振り向いている間、黒目の側の床を赤・白目の側を緑に光らせる。入っていない目は白目のまま（本物のだるまと同じ）。HUD も「黒目の側は うごくな！」
- だるまを作り直した: 卵形の赤い体、金の縁取りの白い顔、太い眉とひげ、お腹に「福」。捕まったときの小さなだるまも同じ見た目に
- ステージ「だるま神社」: 石畳の参道、朱色の鳥居 3 基（額に「達磨」）、垣根、石灯籠、桜、奥の拝殿、目入れの台に筆
- むずかしいモード（夜）: スタート地点の左右の台で選ぶ。数値は `Config.MODES.hard`。嘘のチカチカ（入れ替えない）と、背を向けてすぐ振り向くを追加。v0 の「次に足す順番」2 の「嘘をつくだるま」はここで一部実現
- 真ん中の線の上はどちらの目からも見える扱いにした（線の上を歩けば安全、を防止）
- モード切り替えは全員をスタートに戻す。人が増えたら投票式にするか検討
- 感想「道に障害物が必要かも」→ 参道に絵馬掛け（柵）・賽銭箱・手水鉢。配置は `Config.OBSTACLES`。視界は左右の半分で決まるので「隠れる」障害物ではなく、柵が左右交互に中央線をまたいでふさぎ、抜けるために危ない側へ渡らせる設計。むずかしいモードは柵が 5 枚増える（ServerStorage から出し入れ）。経路探索でゴールまで通れることを確認済み

## 技術の決まりごと

- Rojo プロジェクト。`default.project.json` が入口。Studio で手で置く物はゼロ（全部コードで生成）
- 初期は `rojo build` で `Daruma.rbxl` を作り、Studio で開く方式。ライブ同期（`rojo serve`）は慣れてから
- 公開は当面 Studio の「Publish to Roblox」ボタン。Open Cloud API は公開を自動化したくなったら（無料）
- 数値は全部 `src/shared/Config.luau`。手触りの調整はそこだけ触る
- Roblox 側で課金が発生するまで、費用は一切かからない（Studio、Rojo、API すべて無料）

**2026-10-06（3 回目）: ステージ「渋谷」「富士山」を追加。**
- ステージはラウンドごとに 神社 → 渋谷 → 富士山 と回る（`Config.STAGE_ORDER`）。全員が全部の景色を見られて、続けて遊ぶ理由になる
- 共通の土台（StageBuilder.build）と、ステージの景色・障害物（`src/server/Stages/*.luau`）を分けた。障害物の種類は wall / block / round の 3 つで、ステージごとに見た目が違う
- 渋谷: 歩行者信号がだるまに合わせて赤（見ている）/ 青（背を向けている）に変わる
- 富士山: 富士山は円柱を積んで作っている（遠いので段は見えない）
- 渋谷・富士山の地名は使っているが、実在の店名・ロゴ・ブランドは使っていない（看板はラーメン・カラオケなど一般名詞のみ）

**2026-10-06（4 回目）: 「やりなおす」ボタン。**
